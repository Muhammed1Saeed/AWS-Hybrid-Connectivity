### How traffic flows

- **Internet access from the Spoke:** Spoke1 has no IGW and no NAT. App servers send `0.0.0.0/0` to the TGW, which delivers it to the Hub TGW subnets. `hub-tgw-rt` forwards it to the Hub NAT Gateway, and the NAT sends it out through the IGW. Return traffic comes back through `hub-public-rt` (10.10.0.0/16 via TGW).
- **ALB to app servers:** the ALB (Hub) reaches the app servers (Spoke1) through `hub-alb-rt` (10.10.0.0/16 via TGW). Health checks and requests originate from the ALB subnets.
- **Database isolation:** `spoke1-db-rt` has no `0.0.0.0/0` route, so the database has no path to the internet. It only has routes to the Hub and On-Prem networks.
- **On-Prem:** routes to 192.168.0.0/16 point to the TGW. The VPN and its attachment are owned by another member.

## 4. Security groups

Security groups cannot reference groups in another VPC, so cross-VPC rules use CIDRs.

| Security group | VPC | Inbound |
|---|---|---|
| hub-alb-sg | Hub | TCP 80 from 10.10.0.0/16 and 192.168.0.0/16 |
| hub-bastion-sg | Hub | TCP 22 from `var.bastion_ssh_cidr` |
| spoke1-app-sg | Spoke1 | TCP 80 from 10.0.2.0/24 and 10.0.3.0/24; TCP 22 from 10.0.1.0/24 |
| spoke1-db-sg | Spoke1 | TCP 3306 from 10.10.1.0/24, 10.10.2.0/24 and 192.168.2.0/24 |

## 5. Application tier

- **Internal ALB** `hub-internal-alb` in `hub-pvt-ALB-a` and `hub-pvt-ALB-b`, HTTP listener on port 80.
- **Target group** `spoke1-app-tg`: type `ip`, port 80, health check on `/`, expects HTTP 200.
- **App servers**: two EC2 instances with fixed private IPs, no public IP. User data installs nginx and deploys the static site from GitHub.
- **Bastion**: EC2 in `hub-pub-a` with a public IP. SSH is restricted by `bastion_ssh_cidr`.
- **Database**: RDS MySQL 8.0 in the DB subnet group, not publicly accessible. The master password is generated by AWS and stored in Secrets Manager.

## 6. Connectivity tests (after the leader applies)

Replace `<BASTION_IP>`, `<ALB_DNS>` and `<RDS_ENDPOINT>` with the Terraform outputs.

| # | Test | Command | Expected |
|---|---|---|---|
| 1 | SSH to the bastion | `ssh -i core1-key.pem ec2-user@<BASTION_IP>` | Login succeeds |
| 2 | Website through the ALB | from the bastion: `curl -I http://<ALB_DNS>` | `HTTP/1.1 200 OK` |
| 3 | Target health | `aws elbv2 describe-target-health --target-group-arn <TG_ARN>` | Both targets `healthy` |
| 4 | App server internet access | on an app server: `curl -I https://github.com` | Response received (via TGW and NAT) |
| 5 | App server to DB | on an app server: `nc -zv <RDS_ENDPOINT> 3306` | Connection succeeded |
| 6 | Bastion to DB (must fail) | from the bastion: `nc -zv -w 5 <RDS_ENDPOINT> 3306` | Timeout, blocked by `spoke1-db-sg` |
| 7 | Hub to Spoke | from the bastion: `curl -I http://10.10.1.10` | Blocked (the app SG only allows the ALB subnets on port 80) |

## 7. Notes and open items

1. **Hub subnets have no `availability_zone`.** In `Hub_VPC.tf` they are `(known after apply)`. Add `us-east-1a` for hub-pub-a, hub-pvt-ALB-a and hub-pvt-TGW-a, and `us-east-1b` for hub-pvt-ALB-b and hub-pvt-TGW-b before apply, otherwise the Hub TGW attachment can fail.
2. **TGW attachments** (Hub and Spoke1) are not part of this work. All routes pointing to the TGW need them to exist at apply time. The app servers also need them to reach the internet.
3. **No Auto Scaling Group.** An ASG cannot register itself in an `ip` target group, and the targets are in another VPC, so two fixed EC2 instances are registered explicitly with `availability_zone = "all"`.
4. **The site has no backend.** The static website does not use the database. RDS exists because Core 1 requires it.
5. **Bastion SSH** defaults to `0.0.0.0/0`. Restrict it by setting `bastion_ssh_cidr` to a single IP in a local `terraform.tfvars` (not committed).
6. **Key pair** `core1-key` is created manually in the console and must exist before apply.
